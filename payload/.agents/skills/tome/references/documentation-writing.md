# Writing useful knowledge

Lead with the reader's task and link exact detail. Each fact has one owner; stable
IDs, headings and concise indexes make it discoverable. Reuse project terminology
and documents. Split by responsibility/readership, not a fixed module pack.

Separate confirmed intent, proposed design, observed code and gaps. Record reasons
and source symbols: generated signatures do not explain side effects or business
constraints. Tables help fields/methods; diagrams help architecture when useful.
Verify links and remove seed prompts as actual knowledge is filled in.

Keep continuity short and link detail. Retire superseded claims explicitly. Review
meaning before refreshing metadata. Concision must preserve handoff-critical facts.
